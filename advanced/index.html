Advanced version

The same protection, built for a security team.

Shield360 Endpoint Advanced keeps everything in the standard edition and adds roles, single sign‑on, event search, detection rules, incidents, vulnerability and compliance tracking, and health scores. It runs as two Windows services on PostgreSQL, which the installer can set up for you.

irm https://shield360.biz/advanced/install.ps1 | iex

This is a preview. Install it on a spare server first, not over a server you rely on. The standard edition is still the supported release, and its downloads have not changed.

Note the /advanced/ in the command. The standard edition's command, irm https://shield360.biz/install.ps1 | iex, installs or upgrades the standard edition and never switches a server to Advanced. To move a standard server across, see Move from the standard edition.

How to install Read install.ps1

What it adds

Roles, invites and single sign‑on

Admin, SOC analyst and read‑only users, each with their own sign‑in. Invite people by email with a one‑time link, or let them sign in with Microsoft Entra ID or Google Workspace, pinned to your organisation.

Approve new endpoints

Turn off automatic approval and a newly enrolled machine waits in the Approvals queue until someone confirms it belongs to you.

Event search

Agents forward process starts, network connections, sign‑ins, failed sign‑ins, lockouts, removals from groups and deleted accounts. Search them across the fleet, follow one endpoint's timeline, and find programs that run on only a few machines.

Detection rules

Write your own rules on those events, with a threshold and a time window such as 20 failures in an hour. A rule can count by a field across endpoints, so one account failing on many machines raises an alert on each of them.

Incidents

Open an incident from one or more alerts, give it an owner and a priority, and close it with a reason. Each priority has a response and a resolution target, and a missed target sends a notification.

Vulnerabilities

Missing Windows security updates and installed programs with a known CVE, flagged when CISA lists the CVE as exploited, with its CVSS score and its EPSS chance of exploitation. Deadlines per severity, risk acceptance, and your own additions to the list of programs that are checked.

Compliance

CIS Controls v8.1 and ISO/IEC 27001:2022 scores from what the agents already report, including password, lockout and audit policy, per control and per endpoint, with the change since last week and a CSV report.

Health scores

Every endpoint gets a 0–100 health score with a 7‑day trend. The whole fleet gets a health index with a 30‑day trend, and the console shows exactly how it is worked out.

An overview that tells you what to fix

How many endpoints have each control in effect (antivirus, EDR, automatic isolation, backup, USB control, web filtering), open incidents and exposures, and a setup checklist for a new server.

Dashboards and a monthly report

Five dashboards for endpoints, alerts, vulnerabilities, compliance and EDR activity, and a printable monthly posture report.

Install

One command, from Windows PowerShell opened as Administrator. It downloads the package, checks its SHA‑256, installs PostgreSQL or connects to yours, and installs the two services.

  1. Choose a database

    The installer can install PostgreSQL 17 on this server for you. To use a PostgreSQL 16 or newer you already run, create an empty database and a login that owns it. TimescaleDB is optional.

  2. Run the installer

    It first asks whether to install PostgreSQL here. Answer Y and it does the rest, in about ten minutes. Answer N and give the PostgreSQL server, port, database, login and password. Enter accepts the suggested value.

    irm https://shield360.biz/advanced/install.ps1 | iex

  3. Sign in

    The installer prints the server address and the first admin sign‑in. You choose your own password at first sign‑in.

With PostgreSQL, without questions

Installs PostgreSQL 17 from EnterpriseDB after checking its signature, listening on this server only. Its superuser password is kept for administrators in C:\ProgramData\Shield360 Server\postgresql-superuser.txt.

& ([scriptblock]::Create((irm https://shield360.biz/advanced/install.ps1))) -InstallPostgreSql

Your database, without questions

Give the connection string up front, for a runbook or remote PowerShell.

& ([scriptblock]::Create((irm https://shield360.biz/advanced/install.ps1))) -Connection 'Host=localhost;Database=shield360;Username=shield360;Password=...'

With HTTPS

Without a certificate the server listens on plain HTTP, which is only suitable for a first look.

& ([scriptblock]::Create((irm https://shield360.biz/advanced/install.ps1))) -Port 8443 -CertificatePath C:\certs\shield360.pfx -CertificatePassword ...

Check first

Downloads the package and checks its SHA‑256, and changes nothing on the server.

& ([scriptblock]::Create((irm https://shield360.biz/advanced/install.ps1))) -CheckOnly

Upgrade

Run the same one‑liner on the server. It keeps the database, port and HTTPS certificate already configured and asks nothing. The console's Settings → Server version says when a newer release is out.

irm https://shield360.biz/advanced/install.ps1 | iex

By hand, or offline

Download the package, compare its SHA‑256 with the one under Details, extract it, and run the installer inside from an elevated PowerShell.

.\Install-Shield360Server.ps1 -Connection "Host=localhost;Database=shield360;Username=shield360;Password=..."

Move from the standard edition

On the standard edition's server, from the extracted package. It takes over the port and HTTPS certificate, so agents keep the same address, stops the standard server, and imports endpoints, policies, users with their passwords, alerts and events. The standard server's folder is kept for a rollback. This installs PostgreSQL too; to use your own database, give -Connection instead of -InstallPostgreSql.

.\Install-Shield360Server.ps1 -InstallPostgreSql -ImportFrom "C:\Shield360 Endpoint\server"

Remove

From the extracted package. It removes the services and the firewall rule; the program files and the database are kept.

.\Install-Shield360Server.ps1 -Uninstall
