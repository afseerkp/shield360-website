How it works

Three parts. No moving pieces you don't own.

An agent on each endpoint, one Node.js server with SQLite, and a browser. No cloud tenant, no per‑seat licence server, no third‑party agent to babysit.

01

The agent

Pure Windows PowerShell 5.1 — already on every supported machine. Runs as a SYSTEM scheduled task with a watchdog that restarts it within 5 minutes.

02

The server

Node.js 22.13+ with built‑in SQLite. No npm packages to audit or patch. Runs on Windows Server, Windows or Linux.

03

The console

A fast, focused web UI served with strict security headers. Overview, endpoints, alerts, policies, definitions and audit — nothing you don't need.

Visibility

    Antivirus & attack prevention

    Eleven layers. One policy.

    Shield360 manages Microsoft Defender — built into every supported Windows version — and adds its own prevention layer on top. Configure it once under Protection policies, assign it per endpoint, and pilot safely in Report only mode.

    Antivirus, centrally enforced

    Real‑time, behaviour, script (AMSI), download and cloud protection. Cloud block level, PUA blocking, signature update interval, a daily quick scan and managed exclusions — all from one place.

    Exploit protection

    17 ASR rules — LSASS credential theft, Office macro abuse, obfuscated scripts, PsExec/WMI lateral movement, webshells, USB malware.

    Ransomware

    The advanced ransomware protection rule plus controlled folder access guard the files that matter.

    Malicious sites & C2

    Defender network protection, plus blocklisted domains via hosts file and IPs via the firewall.

    Brute‑force blocking

    Watches failed logons — RDP, SMB and more — and blocks the attacking IP in the firewall for a set time. Trusted IPs stay on an allowlist.

    Blocklist (IOCs)

    SHA‑256 hashes are killed and quarantined. IPs, CIDRs and domains are blocked. Paste whole threat feeds.

    Hardening

    Firewall on, inbound blocked by default. SMBv1, LLMNR and WDigest off. NLA for RDP, PowerShell logging, optional LSA protection.

    Attack detection

    Event‑log watch for log clearing, new accounts, privileged group changes, suspicious services, Defender being disabled and attack‑like PowerShell.

    Virus definitions

    Every endpoint on Microsoft's latest definitions — with a signed server mirror for networks that can't reach Microsoft.

    Response actions & automatic isolation

    Isolate or release, kill a process, quarantine a file, scan a path, remove threats, unblock an IP. And when an endpoint is compromised, it cuts itself off — without waiting for the server.

    Self‑healing by design

    Every 15 minutes the agent re‑applies its policy and reports compliance for each individual setting. Someone switched off PUA protection locally? It's back on the next cycle. Settings managed by Group Policy or Intune take precedence and are reported honestly as non‑compliant.

    Automatic isolation

    When a PC is compromised, it quarantines itself.

    The moment an enabled trigger fires, the agent isolates the endpoint on its own — so it works even while your server is down. All inbound and outbound traffic is blocked, IPv4 and IPv6, internet and LAN. Except one line: back to Shield360, so you stay in control.

    • Survives restarts. Isolation stays on until an admin clicks Release isolation.
    • Works without DNS. The server address is pinned in the hosts file.
    • Server‑safe by default. Servers raise a critical alert instead, and you isolate with one click.

    Virus definitions

    The latest virus database. Everywhere.

    Microsoft publishes new Defender definitions several times a day. Shield360 keeps every endpoint current in three layers — including the ones that can't reach the internet.

    1. 1

      Defender's own updater

      Runs at the interval set in your protection policy. Default: every 4 hours.

      every 4h
    2. 2

      The agent double‑checks

      Every 15 minutes. Stale definitions are updated by the agent itself. Above twice the interval it's non‑compliant; above 3 days it raises an alert.

      every 15m
    3. 3

      Signed server mirror

      The server fetches Microsoft's full package (mpam-fe.exe, ~200 MB) and keeps it only with a valid Microsoft signature. Isolated PCs and offline networks download it from you — and verify the signature again before installing.

      verified twice
    Security design

    A security tool that isn't the weakest link.

    Management tools are high‑value targets. Shield360 is built so a compromised console can't be turned into a remote‑execution platform.

    Per‑agent keys

    Each agent gets its own random key at enrollment. The server stores only a SHA‑256 hash. Removing an endpoint revokes it instantly.

    Fixed action allow‑list

    Remote actions come from a fixed list. The server cannot run arbitrary scripts on your endpoints — by design.

    Rotatable enrollment

    The enrollment token only registers new machines. Rotate it any time without touching enrolled agents.

    scrypt + lockout

    Admin passwords hashed with scrypt. HttpOnly, SameSite=Strict sessions. Five failed logins lock the source IP for five minutes.

    Strict headers

    The console ships with CSP, frame denial and nosniff. HTTPS with your own internal CA certificate is a single command.

    Locked‑down agent

    Config and key live in C:\ProgramData\Shield360, readable only by SYSTEM and Administrators. Full audit log of every action.

    Built‑in alert rules

    Alerts that raise and resolve themselves.

    Sensible rules out of the box, thresholds you can tune in config.json. When the condition clears, the alert closes on its own — no stale queue to triage on Monday.

          FAQ
          
    Questions, answered.
    
          
    Still curious? The README and testing guide ship with every copy, or write to sales@shield360.biz.
    
        
    
        
    
          
    
            Do I need to replace my antivirus?
            
    No. Shield360 uses Microsoft Defender — already built into every supported Windows version — as its engine, and manages it centrally. It also reports third‑party AV where present.
    
          
    
          
    
            Will auto‑isolation take down my production servers?
            
    Not by default. The "Servers: alert only" setting is on out of the box. Servers raise a critical "Compromise detected" alert and you isolate them with one click when you choose to.
    
          
    
          
    
            What happens if my Shield360 server goes offline?
            
    Endpoints keep enforcing their last policy and still isolate themselves when a trigger fires — the decision happens on the agent. When the server returns, everything reconciles on the next check‑in.
    
          
    
          
    
            What does the install script actually do?
            
    It checks for Node.js 22.13+ (installing the LTS with winget if missing), downloads the release package from shield360.biz, verifies its SHA‑256 checksum, extracts it to C:\Shield360 Endpoint, creates an HTTPS certificate and registers the server to start automatically. Upgrades keep your config and data. Read the script before you run it.
    
          
    
          
    
            How do I pilot a policy safely?
            
    Use Report only mode. The agent measures compliance for every setting but changes nothing, and raises alerts instead of isolating. Switch to Enforce when you're happy.
    
          
    
          
    
            Does it work alongside Group Policy or Intune?
            
    Yes. Settings managed by GPO or Intune take precedence, and Shield360 shows them as non‑compliant so you can see exactly where policies disagree.
    
          
    
          
    
            Can the server run arbitrary commands on endpoints?
            
    No. Remote actions come from a fixed allow‑list — scans, signature updates, process and connection listings, restarts with a two‑minute user warning, isolation and the response actions. Nothing else.
